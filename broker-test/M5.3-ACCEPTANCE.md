# M5.3 Acceptance: 5-维 healthcheck status

## TL;DR

`broker/healthcheck.js` v3.0 M4 把所有"没成功"全塞进 `fail`, 用户分不清是凭据过期 / 基础设施不可达 / 自己配错 ssh target. M5.3 把 `fail` 拆成 3 个独立维度, 让 dashboard 一眼分清 "要轮换" / "改 ECS 出网" / "改 broker.yaml" / "正常" / "不支持".

**4 维 → 5 维 (M4 → M5.3)**

| status | 含义 | 用户动作 |
|---|---|---|
| `ok` | 业务验证通过 | 不用动 |
| `expired` | 401/403 真凭据问题 | **轮换凭据** (rotate-secret-ecs.sh) |
| `unreachable` | 基础设施不可达 (DNS / ECONNRESET / RST) | **改 ECS 出网** (Warp / 海外跳板 / 安全组) — 改不了 ECS IP |
| `misconfigured` | 配置错 (缺字段 / ssh target 错 / 端口错) | **改 broker.yaml / secrets/*.yaml** |
| `fail` | 兜底未知错误 | 看 detail 排查 |
| `skipped` | type 不支持 / 无凭据 | 不用动 |

**保留**: `ok` / `expired` / `fail` / `skipped` 含义不变 (后向兼容)

**新增**: `unreachable` / `misconfigured`

## 改动清单

### `broker/healthcheck.js`

- **新增** `export function classifyError(e) → { status, detail }` 纯函数
  - ENOTFOUND / EAI_AGAIN / EAI_FAIL → `unreachable`
  - ECONNRESET / EHOSTUNREACH / ENETUNREACH → `unreachable`
  - "SSL_connect Connection reset" / "read ECONNRESET" in msg → `unreachable`
  - ECONNREFUSED → `misconfigured`
  - ETIMEDOUT / "timeout after Xms" → `misconfigured`
  - 其它 → `fail` (兜底)
- **改** 6 个 check 函数 (github/openai/ssh/aliyun/tencent/aws/cloudflare) 的 `req.on('error')` 全部走 `classifyError`
- **改** `checkSsh` 缺 host 字段: `skipped` → `misconfigured` (语义: ssh_connection 配了但没目标, 是配置错)
- **改** `checkSsh` TCP connect timeout 10s: `fail` → `misconfigured` (语义: 远端不响应, 通常 ssh target 错 / 防火墙 drop)
- **改** `checkAliyun` / `checkTencent` / `checkAws` 缺子凭据: `skipped` → `misconfigured` (主凭据缺仍 `skipped`)
- **改** `checkSecret` ssh_private_key bare: `skipped` → `misconfigured` (需要 wrap 成 ssh_connection)
- **改** `runAll` summary 5 维 (M4 4 维 + unreachable + misconfigured)
- **改** `runAll` last_status 计算看 4 个非 ok 维度 (M4 只看 expired/fail)
- **改** `runAllViaMcp` summary 兜底 5 维

### `broker/mcp-server.js`

### `broker-test/test-healthcheck.js` (+36 断言, 67 → 103)

- tencent_sk 缺 secret_key → misconfigured
- aws_access_key 缺 secret_access_key → misconfigured
- ssh_private_key bare → misconfigured (需要 ssh_connection wrapper)
- github_pat 缺 token → skipped (pickCredential 返 null, 不是配置错)
- 未知 type → skipped

#### checkSsh ECONNREFUSED 1 case (实时 TCP)
- 启 server 立刻 close → 连同 port → ECONNREFUSED → misconfigured

#### runAll summary 5 维 8 cases
- summary 含 ok 字段
- summary 含 expired / unreachable / misconfigured / fail / skipped 字段
- 6 维 sum === total
- last_status: 至少 1 expired → degraded
- persisted.summary 6 维持久化

#### last_status 4 维计算 2 cases
- last_status 是 degraded 或 ok
- last_status 字段类型 string

### 5 secrets 状态归因 (M5.3 之前都笼统是 fail, M5.3 之后精确分类)

| Secret | Status (M5.3) | 用户动作 | 不可控 / 可控 |
|---|---|---|---|
| `ALIYUN_ACCESS_KEY` | ok | 不用动 | — |
| `OPENAI_API_KEY` | **unreachable** | 改 ECS 出网 (Warp / 海外跳板 / 安全组规则) | **不可控** (OpenAI 拒阿里云 IP 段, ECS 47.94.225.76 AS37963 Hangzhou Alibaba Advertising) |
| `IBMC` | **misconfigured** | 改 broker.yaml `IBMC.ssh_connection.host` 为 ECS 可达 IP | **可控** (用户内网配置) |
| `GITHUB_PAT` | **expired** | 跑 rotate-secret-ecs.sh 轮换 PAT | **可控** (用户手动生成新 token) |
| `cloudflare` | **expired** | 跑 rotate-secret-ecs.sh 轮换 token | **可控** (用户手动生成新 token) |

## 用户 action (3 件)

1. **轮换 GITHUB_PAT** (M5.2 已确认 401 真过期)
2. **轮换 cloudflare token** (M5.2 已确认 403 真过期)
3. **改 broker.yaml `IBMC.ssh_connection.host`** (用户内网 192.168.2.100 在 ECS VPC 不可达, 走网关 timeout)

OPENAI 走 `unreachable` (基础设施层), 需要 ECS 出网侧决策 (Warp / 海外跳板), 不在凭据轮换范围.
