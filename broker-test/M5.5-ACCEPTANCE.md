# M5.5 Acceptance: Service ↔ Secret 联动 (call_service 前置检查)

## TL;DR

`/api/v1/proxy/:service` v3.0 不管 `svc.token_secret` 引用 secret 的健康度, 凭据 expired 也照常调上游, 浪费配额 + 触发风控. M5.5 加 service ↔ secret 联动: 当 `svc.token_secret` 是 expired / unreachable / misconfigured / fail 时, broker 提前 503 阻断, **不真去调 upstream**.

**1 个 commit**: `9c1ec0d broker: service-secret-guard 联动 — call_service 前置 503 阻断 (M5.5)`
**测试 5 套件 256/256 PASS** (41 + 45 + 103 + 35 + **32** 新, 224 → 256, +32)

## 改动清单

### 新增 `broker/service-secret-guard.js` (4151 字节)

独立模块, 公开 3 个 API:

```js
export function checkSecretForService(tokenSecret, getSecretStatusFn)
  → { allowed: boolean, status, detail, latency_ms?, ts? }

export function clearSecretGuardCache(name?)
  → 清缓存 (name 缺省清全部)

export function guardHint(status)
  → 'rotate the secret first' | 'fix the upstream network/firewall' | 'fix the secret config' | 'check the secret status'

export const SECRET_GUARD_TTL_MS = 5 * 60 * 1000
```

**5 维 status 分类 (跟 M5.3 healthcheck 一致)**:

| status | allowed | 用户动作 |
|---|---|---|
| `ok` | true | 不用动 |
| `skipped` | true | service 可能不用 secret, 放过 |
| `unknown` | true | 没 healthcheck 数据, 放过 (不阻断) |
| `no_secret` | true | service 没配 token_secret, 放过 |
| `no_check_fn` | true | 注入失败兜底, 不阻断业务 |
| `expired` | **false** | rotate secret |
| `unreachable` | **false** | fix network |
| `misconfigured` | **false** | fix config |
| `fail` | **false** | check secret status |
| 未来 status | **false** | 保守阻断 (默认行为) |

**5 min 内存缓存**: `secretGuardCache` Map, 避免每个 call_service 都查 healthcheck state 读盘.

### 改 `broker/server.js`

- `import { checkSecretForService, clearSecretGuardCache, guardHint } from './service-secret-guard.js'`
- `/api/v1/proxy/:service` handler 加前置检查 (在 canProxy 之后、callUpstream 之前):
  ```js
  const guard = checkSecretForService(svc.token_secret, healthcheckGetSecretStatus);
  if (!guard.allowed) {
    audit({ action: 'proxy_blocked', cn, fp, service, method, path,
            secret: svc.token_secret, secret_status: guard.status, status: 'denied' });
    return jsonError(res, 503,
      `Service ${serviceName} blocked: secret "${svc.token_secret}" is ${guard.status} (${guard.detail}). ` +
      `Action: ${guardHint(guard.status)}. Run "Run Now" healthcheck to refresh.`);
  }
  ```
- 即使放过的 call_service, audit log 也加 `secret_status` 字段 (代理调用上下文)
- `/api/v1/services` GET 返回加 `token_secret` + `secret_health` 字段 (每个 service)

### 改 `broker/dashboard/app.js`

`renderServiceCard` 加 secret 健康度 badge:
- 5 维 status 颜色 (复用 `.hc-badge` ok/expired/unreachable/misconfigured/fail/skipped)
- hover 看 detail
- 没 healthcheck 数据 → "unknown" 灰

## 不变

- 0 新 npm 依赖
- 凭据零接触保持 (guard 内部不读 secret value, 只看 healthcheck state 的 status)
- 后向兼容:
  - 已有 service 配置不变 (默认放过 — 没 token_secret 或没 healthcheck 数据)
  - 系统接口 JSON shape 加 2 字段 (`token_secret` + `secret_health`), 老客户端忽略即可
  - `checkSecretForService` 注入失败时 allowed=true (不阻断业务 — guard 自身坏不影响业务)
- 5 min 缓存对用户透明 (broker 重启清空, healthcheck state 变化后下次 cache miss 重新查)

2. **轮换 cloudflare token** → 让 `cloudflare` service 从 blocked → ok
3. **改 IBMC ssh target** → 跟 service 解耦 (IBMC 没在 services tab 里, 只在 healthcheck)

OPENAI `unreachable` 走网络层 (M5.3 已知问题), 不在凭据轮换范围.
