## M5.6 改动清单

### `broker/healthcheck.js` (核心)

- **新增** alert_history 持久化 (`secrets/alert-history.jsonl`, append-only, last 1000 entries)
  - `loadAlertHistory()` 启动时从 file 读, 同步 `lastChecks` (上次 status, 用于比较变化)
  - `saveAlertHistory()` 写整个数组 (trim 到 ALERT_HISTORY_MAX=1000)
  - `detectChanges(currentChecks)` 返 `{ changes: { name: { from, to, ts } } }`, 同步 `lastChecks`
  - 检测方向: ok → expired / expired → ok / new secret (from=unknown) / removed (to=removed)
- **新增** export `getAlertHistory(limit?)` (供 `/api/v1/admin/alerts/history`)
- **新增** export `clearLastChecks()` (测试用, 清内存 + unlink 文件)
- **改** `runAll` + `runAllViaMcp`: 跑完 healthcheck 后 `detectChanges`, 有变化写 alert entry + emit `status_change` 事件
- **导入** `unlinkSync` (clearLastChecks 用)
- **改** 模块注释: 加 M5.6 设计说明

### `broker/server.js`

- **加** import `getAlertHistory as healthcheckGetAlertHistory` from healthcheck.js
- **新增** GET `/api/v1/admin/healthcheck/stream` (SSE, admin only):
  ```
  event: ready         — 初次连接
  event: run_complete  — 每次 healthcheck 跑完 (full state)
  event: status_change — 状态变化 (alert history entry)
  ```
  - 启动时立即推 1 次当前 state
  - 30 min 自动关 (跟 audit stream 一致)
  - 客户端断开自动清 listeners
- **新增** GET `/api/v1/admin/alerts/history?limit=50` (admin only): 返 alert_history 时间线

### `broker/dashboard/home.js`

- **新增** SSE 客户端 (`startAlertStream` / `stopAlertStream` / `flashStatusChange`)
  - `EventSource('/api/v1/admin/healthcheck/stream', { withCredentials: true })`
  - 监听 `run_complete` → 刷新 healthcheck card
  - 监听 `status_change` → 触发 `flashStatusChange(data)`
- **flashStatusChange**:
  - 加 `alert-flash` class 到 healthcheck card (3s 后自动移除)
  - 浏览器通知 (Notification API, 用 `tag: 'broker-alert'` 去重)
  - 自动 `loadAll()` 刷新
- `alertSeenIds` Set 去重 (避免 SSE 重连后重放同一条)
- 启动 2s 后再连 SSE (避免 init 期间 race)

### `broker/dashboard/style.css`

- **新增** `@keyframes alert-flash-pulse` (红点 1s ease-in-out 3 次, box-shadow 渐变)
- **新增** `.alert-flash` class (红边框 + 🔴 icon 在 h3 前)

## M5.9 改动清单

### `broker/server.js`

- **改** `normalizeSecretEntry(name, entry)`:
  - 加 `last_rotated_at`: default = `entry.last_rotated_at || entry.updated_at || now`
  - 加 `rotation_history`: default = `Array.isArray(entry.rotation_history) ? entry.rotation_history : []`
- **改** GET `/api/v1/rotate/:name` handler (admin only, 实际写):
  - 读 body `{ note?, source? }` (凭据零接触, **不**接受 value)
  - `last_rotated_at = now`
  - `rotation_history.unshift({ ts: now, by: ctx.cn, note, source })`, cap 50
  - 持久化到 `secrets-detail.json` (SOPS 加密)
  - audit `action='rotate'`, `status='ok'`, `source`, `note`
  - 返 `{ rotated, last_rotated_at, rotation_count, note }`
- **改** GET `/api/v1/secrets` (user): 加 `last_rotated_at` (admin 路径已有)
- **改** GET `/api/v1/admin/secrets`: 加 `rotation_history` (前 10 条, 倒序)

### `broker/dashboard/admin/secrets.js`

- **改** `renderTable`:
  - 加 "🔄 Last rotated" 区块 (timestamp + `rotation_policy_days` 提示已过/剩多少天)
  - 加 "📜 N 次轮换历史" `<details>` 展开, 显示前 10 条 timeline
  - "🔄 轮换" 按钮 (admin only) → 调 `confirmRotate(name)`
- **新增** `confirmRotate(name)`:
  - `prompt("轮换 X? 可选备注")` → POST `/api/v1/rotate/:name` body `{ note, source: 'admin-ui' }`
  - 失败 alert, 成功 reload secrets

## 不变

- 0 新 npm 依赖
- 凭据零接触保持: `/api/v1/rotate/:name` **不**接受 value, 只记录"我刚轮换了 X"
- 公开 API 兼容: SSE 是新加 (不破坏老客户端), alerts/history 是新加
- 后向兼容:
  - 老 secret 没 `last_rotated_at` 时 fallback `updated_at` (用户视角看不出区别)
  - 老 secret 没 `rotation_history` 时 fallback `[]`
  - alert_history.jsonl 不存在时 `loadAlertHistory` 静默返空
- .gitignore 加 `secrets/healthcheck-state.json`, `secrets/alert-history.jsonl`, `secrets/secrets-detail.json` (运行时产物, 含 cert fp / 凭据 detail, 不入 git)
- SSE 30 min 自动关, 防连接堆积
- dashboard 浏览器通知是 best-effort (用户没授权也能用, 只是收不到通知)
