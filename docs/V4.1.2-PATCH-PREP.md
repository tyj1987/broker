## 4. Performance: auto-rotate cache decision

### 4.1 Current state (V4.1.0)

`broker/lib/auto-rotate.js`:
- Checks secret age on every secret access
- If `now - last_rotated_at > interval_days - warning_days` → warn
- If `now - last_rotated_at > interval_days` → auto-rotate
- Auto-rotate = SOPS encrypt + git commit + restart (slow!)

**Problem**: 1000 secrets × 10 req/sec = 10000 secret access/sec
= 10000 age check/sec
= 10000 potential auto-rotate triggers/day
= lots of git commits (slow!)

### 4.2 V4.1.2 design

**Cache the auto-rotate decision**:
- Key: `secret_name`
- Value: `{ last_decided: timestamp, decision: 'no-rotate' | 'warn' | 'rotate' }`
- TTL: `min(60s, interval_days / 100)` — refreshes every minute OR when secret is updated
- Storage: `BrokerCache` (in-memory, 5-min TTL) + optional Redis (V4.2.0)

```typescript
// broker/lib/auto-rotate.js (V4.1.2 enhanced)
async function shouldAutoRotate(secretName: string, secretConfig: SecretConfig): Promise<Decision> {
  const cached = await cache.get(`autorotate:${secretName}`);
  if (cached && Date.now() - cached.last_decided < 60_000) {
    return cached.decision;  // 'no-rotate' | 'warn' | 'rotate'
  }

  // Re-decide
  const decision = computeDecision(secretConfig);
  await cache.set(`autorotate:${secretName}`, { last_decided: Date.now(), decision });
  return decision;
}
```

**Performance impact**:
- Before: 10000 decisions/sec
- After: 1 decision/sec per secret (1000 decisions/sec total) — same
- BUT: actual git commits = once per secret per `interval_days / 2` (typically 45 days)
- Before: git commit every secret rotation (could be 100/day)
- After: git commit = once per decision change (much less)

**Test target**: `broker-test/test-auto-rotate-cache.js` (15 tests):
- Cache hit returns same decision
- Cache miss recomputes
- TTL refreshes
- Secret update invalidates cache
- Concurrent requests don't double-decide (lock)

## 6. Patch SLA

V4.1.2 is a **patch release** (backward-compatible, no new features).
Per [SemVer](https://semver.org/):

- **v4.1.x.y hotfix**: emergency fix for Critical/High, 7 days
- **v4.1.x patch**: routine fix, 30-90 days, 0 vulns
- **v4.x.0 minor**: new features, ~6 months
- **v5.0.0 major**: breaking changes, ~12 months

**V4.1.2 SLA**:
- Released by 2027-01-31 (ROADMAP target)
- Includes: all V4.1.1 community-reported bugs (High/Medium) + Critical/High bug bounty
- Excludes: new features (defer to V4.2.0)
- Backward compat: 100% (any V4.1.x install upgrades in-place)
